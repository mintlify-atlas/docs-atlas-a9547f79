JyutTranslate is a monorepo with two apps: `apps/api` (an Express proxy that handles LLM calls, Azure Speech, and Supabase metering) and `apps/web` (the React/Vite PWA). You start both dev servers independently so that Vite can proxy `/api` requests to the Express server on port `8787`. The only mandatory secret is `OPENAI_API_KEY`; the Azure keys are optional and unlock higher-quality speech and camera OCR.

## Prerequisites

- **Node.js 20+** and **npm 10+**
- An OpenAI-compatible API key (e.g. DeepSeek at `https://api.deepseek.com/v1`, Ollama at `http://127.0.0.1:11434/v1`, or OpenAI directly)
- *(Optional)* Azure Cognitive Services Speech key + region for STT/TTS
- *(Optional)* Azure Computer Vision key + endpoint for Cam OCR

## Setup Steps

<Steps>
  <Step title="Clone the repository">
    Clone the repo and move into the project root:

    ```bash
    git clone https://github.com/henrywguan/yuetranslation.git
    cd yuetranslation
    ```
  </Step>

  <Step title="Copy the API environment file">
    The API server reads secrets from `apps/api/.env`. Copy the example file to create it:

    ```bash
    cp apps/api/.env.example apps/api/.env
    ```

    <Note>
      The web app (`apps/web`) has its own `.env.example` for optional Supabase and deep-link variables baked in at build time. For a quick local run those are not required — the API hands the Supabase anon key to the frontend at runtime via `/api/auth-config`.
    </Note>
  </Step>

  <Step title="Add your API keys">
    Open `apps/api/.env` in your editor and fill in the values you have. The table below covers every variable in the file:

    **Required for LLM translation**

    | Variable | Description |
    |---|---|
    | `OPENAI_API_KEY` | Your OpenAI-compatible API key. Works with OpenAI, DeepSeek, Ollama, or any `v1/chat/completions` endpoint. |
    | `OPENAI_BASE_URL` | *(Optional)* Override the API base URL. E.g. `https://api.deepseek.com/v1` for DeepSeek or `http://127.0.0.1:11434/v1` for Ollama. Leave blank for OpenAI. |
    | `OPENAI_MODEL` | *(Optional)* Model name to use. Defaults to `gpt-4o-mini`. |

    **Speech (STT / TTS)**

    | Variable | Description |
    |---|---|
    | `AZURE_SPEECH_KEY` | Azure Cognitive Services Speech resource key. Unlocks `zh-HK` streaming STT and neural TTS. Without this, the browser falls back to Web Speech API. |
    | `AZURE_SPEECH_REGION` | Azure region for the Speech resource. Defaults to `eastasia`. |

    **Camera OCR**

    | Variable | Description |
    |---|---|
    | `AZURE_VISION_KEY` | Azure Computer Vision (multi-service) resource key. Required for Cam AR, Upload, and Document OCR. A Speech-only key does **not** unlock OCR. |
    | `AZURE_VISION_ENDPOINT` | Full endpoint URL for your Computer Vision resource, e.g. `https://your-resource.cognitiveservices.azure.com/`. |

    **AI Vision fallback (optional)**

    | Variable | Description |
    |---|---|
    | `OPENAI_VISION_MODEL` | Model for multimodal OCR fallback (e.g. `deepseek-v4-flash-vision-exp`). Leave blank to disable. |
    | `OPENAI_VISION_API_KEY` | API key for the vision model. Defaults to `OPENAI_API_KEY` if omitted. |
    | `OPENAI_VISION_BASE_URL` | Base URL for the vision model. Defaults to `OPENAI_BASE_URL` if omitted. |

    **Supabase (auth & metering)**

    | Variable | Description |
    |---|---|
    | `SUPABASE_URL` | Your Supabase project URL. |
    | `SUPABASE_SERVICE_ROLE` | Supabase service-role secret key (server-side only — never expose to the browser). |
    | `SUPABASE_ANON_KEY` | Supabase anon/public key. Also set as `VITE_SUPABASE_ANON_KEY` in `apps/web/.env` if you need it baked in at build time. |

    **Stripe (payments)**

    | Variable | Description |
    |---|---|
    | `STRIPE_SECRET_KEY` | Stripe secret key for creating Checkout sessions. |
    | `STRIPE_WEBHOOK_SECRET` | Webhook signing secret from the Stripe Dashboard. |
    | `STRIPE_PRICE_FAMILY_MONTH` | Stripe Price ID for the Family monthly plan. |
    | `STRIPE_PRICE_FAMILY_YEAR` | Stripe Price ID for the Family annual plan. |
    | `STRIPE_PRICE_BUSINESS_MONTH` | Stripe Price ID for the Business monthly plan. |
    | `STRIPE_PRICE_BUSINESS_YEAR` | Stripe Price ID for the Business annual plan. |

    **Entitlement limits (optional overrides)**

    | Variable | Default | Description |
    |---|---|---|
    | `PORT` | `8787` | Port the Express API listens on. |
    | `YUE_OPEN_MODE` | `1` (local) | Set `1` locally for Family-like limits without metering. Keep `0` in production. |
    | `YUE_FREE_LIVE_MINUTES` | `60` | Monthly live mic minutes for Free accounts. |
    | `YUE_FREE_TTS_CHARS` | `30000` | Monthly TTS character cap for Free accounts. |
    | `YUE_FREE_CAMERA_SCANS` | `120` | Monthly Cam scan credits for Free accounts. |
    | `YUE_FREE_DOCS_PAGES` | `40` | Monthly Document pages for Free accounts. |
    | `YUE_GUEST_CAMERA_SCANS` | `30` | Trial Cam scans for guests (no sign-in). |
    | `YUE_FAMILY_LIVE_MINUTES` | `480` | Monthly live minutes for Family plan. |
    | `YUE_BUSINESS_LIVE_MINUTES` | `2400` | Monthly live minutes for Business plan. |
    | `YUE_APP_URL` | `http://localhost:5173` | Public app URL — used in Stripe redirects and CORS. |

    A minimal `.env` for quick local testing looks like this:

    ```ini title="apps/api/.env (minimal)"
    PORT=8787
    OPENAI_API_KEY=sk-your-key-here
    OPENAI_BASE_URL=https://api.deepseek.com/v1
    OPENAI_MODEL=deepseek-chat
    YUE_OPEN_MODE=1
    YUE_APP_URL=http://localhost:5173
    ```
  </Step>

  <Step title="Install dependencies">
    Install packages for the API and web app separately:

    ```bash
    npm install --prefix apps/api
    npm install --prefix apps/web
    ```
  </Step>

  <Step title="Start the development servers">
    Open two terminal windows and start each server:

    ```bash title="Terminal 1 — API server"
    npm run dev:api
    ```

    ```bash title="Terminal 2 — Vite dev server"
    npm run dev:web
    ```

    The API server starts on `http://localhost:8787` and the Vite dev server starts on `http://localhost:5173`. Vite proxies all `/api` requests to the Express server automatically.

    <Warning>
      If you edit `apps/api/.env` after `dev:api` is already running, you must **restart** `dev:api` for the new values to take effect. Vite hot-reload does not restart the Express process.
    </Warning>
  </Step>

  <Step title="Verify the API health endpoint">
    With both servers running, confirm the API is reading your key correctly:

    ```bash
    curl -s http://localhost:8787/api/health
    ```

    A successful response looks like this:

    ```json
    {
      "openai": true,
      "demo": false,
      "engine": "openai"
    }
    ```

    | Field | Value | Meaning |
    |---|---|---|
    | `openai` | `true` | `OPENAI_API_KEY` is present and the model path is active. |
    | `openai` | `false` | No API key found — translation will fall back to demo mode. |
    | `demo` | `false` | The server will use the LLM for unknown phrases. |
    | `demo` | `true` | No key set — unknown phrases will be prefixed with `（示範）`. |
    | `engine` | `"openai"` | The active translation engine. `"dictionary"` means a phrase-memory hit was returned without any LLM call. |
  </Step>
</Steps>

## Demo Mode

When no `OPENAI_API_KEY` is set, JyutTranslate runs in demo mode. The built-in Cantonese phrase dictionary still returns **real Cantonese translations** for common phrases — the health endpoint will show `"engine": "dictionary"` for those hits. For any text that does not match the dictionary, the translation is prefixed with `（示範）` to signal that the result is a placeholder, not a live LLM translation.

<Info>
  Demo mode is useful for verifying that the UI, routing, TTS playback, and Jyutping display all work correctly without spending any API credits.
</Info>

## Open the App

With both servers running, navigate to [http://localhost:5173](http://localhost:5173) in your browser. To test mic and camera features on a **phone**, you need an HTTPS tunnel — see the [Phone Testing guide](/local-phone-testing).
