JyutTranslate is a monorepo with two apps: `apps/web` (a React/Vite PWA) and `apps/api` (an Express server). On Vercel, the web app is deployed as a static SPA from `apps/web/dist` while the API runs as a single serverless function defined in `api/index.ts` at the repo root. The `api/index.ts` entry point simply re-exports the Express app from `apps/api/src/app.js`, keeping the Vercel function thin and the API source self-contained.

---

## Project structure

```text
yuetranslation/
├── apps/
│   ├── web/          # React/Vite PWA (output → apps/web/dist)
│   └── api/          # Express API source
├── api/
│   └── index.ts      # Vercel serverless entry — re-exports apps/api/src/app.js
├── packages/
│   └── yue-shared/   # Shared types and utilities
└── vercel.json       # Vercel project configuration
```

The `api/index.ts` entry is intentionally minimal:

```ts title="api/index.ts"
import app from '../apps/api/src/app.js'

export default app
```

## vercel.json configuration

The `vercel.json` at the repo root configures the build, routing, headers, and production environment overrides.

<Tabs>
  <Tab title="Build & output">
    ```json title="vercel.json (build)"
    {
      "buildCommand": "npm run build:vercel",
      "outputDirectory": "apps/web/dist",
      "installCommand": "npm ci && npm ci --prefix packages/yue-shared && npm ci --prefix api && npm ci --prefix apps/web && npm ci --prefix apps/api"
    }
    ```

    The `installCommand` installs dependencies for all workspaces in sequence. `build:vercel` runs the Vite web build and compiles the API email templates for the serverless runtime.
  </Tab>
  <Tab title="Serverless function">
    ```json title="vercel.json (functions)"
    {
      "functions": {
        "api/index.ts": {
          "maxDuration": 60,
          "memory": 1024,
          "includeFiles": "{apps/api/src/canto/data/**,apps/api/src/emails/assets/**,apps/api/src/emails/compiled/**,packages/yue-shared/**}"
        }
      }
    }
    ```

    The function runs for up to **60 seconds** with **1 GB of memory**. `includeFiles` bundles the Cantonese dictionary data, email template assets, compiled email JS, and the shared package into the function's deployment artifact.
  </Tab>
  <Tab title="Rewrites & redirects">
    ```json title="vercel.json (routing)"
    {
      "rewrites": [
        { "source": "/api/(.*)", "destination": "/api" },
        {
          "source": "/((?!api/|robots\\.txt$|sitemap\\.xml$|og\\.png$|favicon\\.svg$|manifest\\.webmanifest$|sw\\.js$).*)",
          "destination": "/index.html"
        }
      ],
      "redirects": [
        {
          "source": "/:path*",
          "has": [{ "type": "host", "value": "jyuttranslate.com" }],
          "destination": "https://www.jyuttranslate.com/:path*",
          "permanent": true
        }
      ]
    }
    ```

    All `/api/*` requests are rewritten to the single serverless function. All other requests (except known static assets) fall through to `index.html` for SPA client-side routing. Apex domain traffic (`jyuttranslate.com`) is permanently redirected to the canonical `www` URL.
  </Tab>
  <Tab title="Security headers">
    ```json title="vercel.json (headers)"
    {
      "headers": [
        {
          "source": "/(.*)",
          "headers": [
            {
              "key": "Strict-Transport-Security",
              "value": "max-age=63072000; includeSubDomains; preload"
            },
            { "key": "X-Content-Type-Options", "value": "nosniff" },
            { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" }
          ]
        }
      ]
    }
    ```

    HSTS is set to 2 years with preload and `includeSubDomains`. All responses also include `X-Content-Type-Options: nosniff` and a strict referrer policy.
  </Tab>
  <Tab title="Production env overrides">
    ```json title="vercel.json (env)"
    {
      "env": {
        "YUE_OPEN_MODE": "0",
        "YUE_REQUIRE_LOGIN": "1",
        "YUE_FREE_ALLOW_TTS": "1",
        "YUE_FREE_TTS_CHARS": "30000",
        "YUE_FREE_LIVE_MINUTES": "60",
        "YUE_FAMILY_LIVE_MINUTES": "480",
        "YUE_GUEST_LIVE_MINUTES": "30",
        "YUE_GUEST_CAMERA_SCANS": "30"
      }
    }
    ```

    These values are baked into the Vercel build and take precedence over the dashboard environment variables. Key production rules:
    - `YUE_OPEN_MODE=0` — fail-closed metering and login gates enforced
    - `YUE_REQUIRE_LOGIN=1` — sign-in required before Live mic and Cam
    - Guests receive a 30-minute Live trial and 30 Cam scan trial

    <Warning>
      Do not set `YUE_OPEN_MODE=1` in production. Open mode bypasses all metering and plan gates, granting every visitor Family-like limits.
    </Warning>
  </Tab>
</Tabs>

## Deploy to Vercel

<Steps>
  <Step title="Import the repository">
    Go to [vercel.com/new](https://vercel.com/new), click **Import Git Repository**, and select the `yuetranslation` repo. Vercel will detect the `vercel.json` and pre-fill the build settings automatically.
  </Step>
  <Step title="Set environment variables">
    In **Vercel Dashboard → Project → Settings → Environment Variables**, add all the variables from `apps/api/.env.example`. The table below lists the minimum required set for a functional production deployment:

    <CardGroup cols={2}>
      <Card title="Azure" icon="cloud">
        - `AZURE_SPEECH_KEY`
        - `AZURE_SPEECH_REGION`
        - `AZURE_VISION_KEY`
        - `AZURE_VISION_ENDPOINT`
      </Card>
      <Card title="OpenAI / LLM" icon="robot">
        - `OPENAI_API_KEY`
        - `OPENAI_MODEL`
        - `OPENAI_BASE_URL` *(if not OpenAI)*
      </Card>
      <Card title="Supabase" icon="database">
        - `SUPABASE_URL`
        - `SUPABASE_SERVICE_ROLE`
        - `SUPABASE_ANON_KEY`
        - `VITE_SUPABASE_URL` *(build-time)*
        - `VITE_SUPABASE_ANON_KEY` *(build-time)*
      </Card>
      <Card title="Stripe" icon="credit-card">
        - `STRIPE_SECRET_KEY`
        - `STRIPE_WEBHOOK_SECRET`
        - `STRIPE_PRICE_FAMILY_MONTH`
        - `STRIPE_PRICE_FAMILY_YEAR`
        - `STRIPE_PRICE_BUSINESS_MONTH`
        - `STRIPE_PRICE_BUSINESS_YEAR`
      </Card>
      <Card title="App & admin" icon="gear">
        - `YUE_APP_URL` → `https://www.jyuttranslate.com`
        - `YUE_ADMIN_EMAILS`
      </Card>
      <Card title="Email / Resend" icon="envelope">
        - `RESEND_API_KEY`
        - `RESEND_AUDIENCE_ID`
        - `YUE_NOTIFY_FROM`
        - `SUPABASE_AUTH_HOOK_SECRET`
        - `SUPABASE_SEND_EMAIL_HOOK_SECRET`
      </Card>
    </CardGroup>

    See [Environment Variables](/self-hosting/environment) for the full reference including VAPID keys, plan limit overrides, and optional flags.
  </Step>
  <Step title="Deploy">
    Click **Deploy**. Vercel runs the install command, then `npm run build:vercel`. The static output is served from `apps/web/dist` and the `api/index.ts` function is deployed as a serverless handler at the `/api` route prefix.
  </Step>
  <Step title="Add custom domain">
    In **Vercel Dashboard → Project → Settings → Domains**, add both `www.jyuttranslate.com` and `jyuttranslate.com`. The `vercel.json` redirect rule automatically sends apex traffic to the `www` canonical URL.
  </Step>
</Steps>

## Register the Stripe webhook

Stripe must be told where to send billing events after checkout completes.

<Steps>
  <Step title="Create the webhook endpoint">
    In **Stripe Dashboard → Developers → Webhooks**, click **Add endpoint**:
    - **Endpoint URL:** `https://www.jyuttranslate.com/api/billing/webhook`
    - **Events to listen to:** `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`
  </Step>
  <Step title="Copy the signing secret">
    After saving, click the endpoint and reveal the **Signing secret** (`whsec_…`). Set it in Vercel:

    ```bash
    STRIPE_WEBHOOK_SECRET=whsec_...
    ```

    Redeploy the API so the new secret takes effect.
  </Step>
</Steps>

## CORS configuration

The following origins are always included in the CORS allow-list and require no configuration:

| Origin | Notes |
|---|---|
| `https://www.jyuttranslate.com` | Production canonical |
| `https://jyuttranslate.com` | Apex (redirects to www) |
| `https://jyuttranslate.vercel.app` | Vercel preview domain |
| `http://localhost:5173` | Default Vite dev server |

To allow additional origins (e.g. a custom preview domain or a staging environment), set the `YUE_CORS_ORIGINS` variable as a comma-separated list:

```bash
YUE_CORS_ORIGINS=https://staging.example.com,https://preview.example.com
```

## GitHub Actions preview workflow

Every pull request triggers a workflow that waits for the Vercel Preview deployment to become ready before marking the PR check as passed. No Vercel token is required — the workflow reads deployment state from GitHub's Deployments API, which Vercel's GitHub integration populates automatically.

```yaml title=".github/workflows/vercel-preview.yml"
name: Vercel preview

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]

concurrency:
  group: vercel-preview-${{ github.event.pull_request.number }}
  cancel-in-progress: true

jobs:
  wait-vercel:
    name: Wait for Vercel Preview
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - name: Wait for Vercel Preview deployment
        id: vercel
        uses: vercel/wait-for-deployment-action@0e2b0c5c5cce31f1648108aeec56467187aca037
        with:
          environment: preview
          timeout: 900
          check-interval: 15
          require-deployment-id: false

      - name: Confirm Preview URL responds
        env:
          URL: ${{ steps.vercel.outputs.deployment-url }}
          STATE: ${{ steps.vercel.outputs.deployment-state }}
        run: |
          code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 30 "${URL}/")
          case "${code}" in
            200|304|301|302|307|308) exit 0 ;;
            *) echo "::error::Preview shell did not respond (got ${code})"; exit 1 ;;
          esac
```

The workflow polls every 15 seconds for up to 15 minutes. A 2xx or 3xx HTTP response from the preview URL marks the check as successful. Concurrency is scoped per PR number so only the latest push is checked.

## Local development

For local development, copy `.env.example`, set your API keys, and start both servers:

```bash
cp apps/api/.env.example apps/api/.env
# Edit apps/api/.env — add OPENAI_API_KEY, AZURE_SPEECH_KEY, etc.

npm install --prefix apps/api
npm install --prefix apps/web

npm run dev:api   # Express on http://localhost:8787
npm run dev:web   # Vite on http://localhost:5173
```

Confirm the API is healthy:

```bash
curl -s http://localhost:8787/api/health
```

A response with `"openai": true` and `"demo": false` confirms the LLM path is active. Phrase-memory hits return real Cantonese without any API key (`"engine": "dictionary"`).

<Tip>
  To test live microphone on a phone over your local network, run `npm run dev:tunnel` to start a Cloudflare tunnel. Browsers block microphone access on plain `http://192.168.x.x` URLs — the tunnel provides a trusted HTTPS address.
</Tip>
