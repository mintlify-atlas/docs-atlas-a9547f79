JyutTranslate's Express API (`apps/api`) and Vite web app (`apps/web`) are configured entirely through environment variables. Copy `apps/api/.env.example` to `apps/api/.env` and fill in the values below before starting local development or deploying to Vercel. Variables marked **Required** must be set for the relevant feature to work; **Optional** variables have safe defaults that are noted inline.

<Note>
  On Vercel, all API variables are set in the **Vercel Dashboard → Project → Settings → Environment Variables**. The `vercel.json` `env` block hard-codes a small set of production overrides (e.g. `YUE_OPEN_MODE=0`) that take precedence over dashboard values — see the [Deployment guide](/self-hosting/deployment) for details.
</Note>

## 1. Server

<Accordion title="PORT">

| Field | Value |
|---|---|
| **Variable** | `PORT` |
| **Default** | `8787` |
| **Required** | Optional |

The port the Express API listens on locally. Vercel ignores this variable — serverless functions do not bind to a port.

</Accordion>

## 2. Azure Speech

Azure Cognitive Services Speech powers real-time Cantonese STT (`zh-HK`) and TTS across all plans.

<Accordion title="AZURE_SPEECH_KEY">

| Field | Value |
|---|---|
| **Variable** | `AZURE_SPEECH_KEY` |
| **Default** | _(empty)_ |
| **Required** | Required for live mic / TTS |

Your Azure Speech resource API key. Found in **Azure Portal → Speech resource → Keys and Endpoint**.

</Accordion>

<Accordion title="AZURE_SPEECH_REGION">

| Field | Value |
|---|---|
| **Variable** | `AZURE_SPEECH_REGION` |
| **Default** | `eastasia` |
| **Required** | Required for live mic / TTS |

The Azure region where your Speech resource is deployed. Must match the region shown in **Azure Portal → Speech resource → Overview**.

</Accordion>

<Accordion title="AZURE_VISION_KEY">

|---|---|
| **Variable** | `AZURE_VISION_KEY` |
| **Default** | _(empty)_ |
| **Required** | Required for Cam |

API key for the Azure Computer Vision or multi-service resource.

</Accordion>

<Accordion title="AZURE_VISION_ENDPOINT">

| Field | Value |
|---|---|
| **Variable** | `AZURE_VISION_ENDPOINT` |
| **Default** | _(empty)_ |
| **Required** | Required for Cam |

Full HTTPS endpoint URL for the Vision resource (e.g. `https://eastasia.api.cognitive.microsoft.com/`). Found in **Azure Portal → Vision resource → Keys and Endpoint**.

</Accordion>

<Accordion title="AZURE_VISION_REGION">

| Field | Value |
|---|---|

Azure region for the Vision resource. Only needed when `AZURE_VISION_ENDPOINT` is omitted.

</Accordion>

## 4. OpenAI / LLM

JyutTranslate uses an OpenAI-compatible API for colloquial Cantonese translation and, optionally, a separate model for camera OCR fallback (calligraphy / foil text).

<Accordion title="OPENAI_API_KEY">

| Field | Value |
|---|---|
| **Variable** | `OPENAI_API_KEY` |
| **Default** | _(empty)_ |
| **Required** | Required for translation |

API key for your LLM provider (OpenAI, DeepSeek, Ollama, etc.).

</Accordion>

<Accordion title="OPENAI_BASE_URL">

| Field | Value |
|---|---|
| **Variable** | `OPENAI_BASE_URL` |
| **Default** | _(empty — uses OpenAI's default)_ |
| **Required** | Optional |

Override the OpenAI-compatible base URL. Common values:
- Ollama local: `http://127.0.0.1:11434/v1`
- DeepSeek: `https://api.deepseek.com/v1`

</Accordion>

<Accordion title="OPENAI_MODEL">

| Field | Value |
|---|---|
| **Variable** | `OPENAI_MODEL` |
| **Default** | `gpt-4o-mini` |
| **Required** | Optional |

The chat model used for translation. Must be available on the provider set in `OPENAI_BASE_URL`.

</Accordion>

<Accordion title="OPENAI_VISION_API_KEY">

| Field | Value |
|---|---|
| **Variable** | `OPENAI_VISION_API_KEY` |
| **Default** | _(falls back to `OPENAI_API_KEY`)_ |
| **Required** | Optional |

API key for the multimodal vision model used as a silent OCR fallback in Cam (calligraphy / foil text). Defaults to the same key as `OPENAI_API_KEY` when left empty.

</Accordion>

<Accordion title="OPENAI_VISION_BASE_URL">

| Field | Value |
|---|---|
| **Variable** | `OPENAI_VISION_BASE_URL` |
| **Default** | _(falls back to `OPENAI_BASE_URL`)_ |
| **Required** | Optional |

Base URL for the vision LLM provider, if different from the translation model.

</Accordion>

<Accordion title="OPENAI_VISION_MODEL">

| Field | Value |
|---|---|
| **Variable** | `OPENAI_VISION_MODEL` |
| **Default** | _(empty — fallback off)_ |
| **Required** | Optional |

The vision model for silent OCR fallback. Setting this to an empty string disables the LLM camera fallback entirely. Example: `deepseek-v4-flash-vision-exp`.

</Accordion>

## 5. Plan Limits

These variables override the hard-coded monthly caps and feature gates for each plan tier. All values are integers (minutes, characters, or scan counts) unless noted.

<Accordion title="Free plan">

| Variable | Default | Description |
|---|---|---|
| `YUE_FREE_LIVE_MINUTES` | `60` | Monthly live-mic minutes for Free users |
| `YUE_FREE_TTS_CHARS` | `30000` | Monthly tap-to-play TTS character cap (hard gate) |
| `YUE_FREE_CAMERA_SCANS` | `120` | Monthly Cam scan credits (hard gate) |
| `YUE_FREE_DOCS_PAGES` | `40` | Monthly Documents pages (hard gate) |
| `YUE_FREE_AI_VISION_COUNT` | `200` | Monthly LLM OCR fallback cap for Free users |
| `YUE_FREE_ALLOW_LIVE` | `1` | `1` = Live mic allowed for Free; `0` = gated |
| `YUE_FREE_ALLOW_TTS` | `1` | `1` = TTS allowed for Free; `0` = gated |
| `YUE_FREE_ALLOW_CAMERA` | `1` | `1` = Cam allowed for Free; `0` = gated |

</Accordion>

<Accordion title="Family plan">

| Variable | Default | Description |
|---|---|---|
| `YUE_FAMILY_LIVE_MINUTES` | `480` | Monthly live-mic minutes for Family subscribers |
| `YUE_FAMILY_TTS_CHARS` | `200000` | Retained for reference — Family TTS is unlimited in entitlements |
| `YUE_FAMILY_CAMERA_SCANS` | `800` | Monthly Cam scan credits for Family subscribers |
| `YUE_FAMILY_DOCS_PAGES` | `400` | Monthly Documents pages for Family subscribers |
| `YUE_FAMILY_AI_VISION_COUNT` | `2000` | Monthly LLM OCR fallback cap for Family subscribers |

</Accordion>

<Accordion title="Business plan">

| Variable | Default | Description |
|---|---|---|
| `YUE_BUSINESS_LIVE_MINUTES` | `2400` | Monthly live-mic minutes for Business subscribers |
| `YUE_BUSINESS_TTS_CHARS` | `500000` | Retained for reference — Business TTS is unlimited in entitlements |
| `YUE_BUSINESS_AI_VISION_COUNT` | `10000` | Monthly LLM OCR fallback cap for Business subscribers |

</Accordion>

<Accordion title="Guest (unauthenticated) trial">

| Variable | Default | Description |
|---|---|---|
| `YUE_GUEST_LIVE_MINUTES` | `0` | Trial live-mic minutes for unauthenticated guests (production sets `30` via `vercel.json`) |
| `YUE_GUEST_CAMERA_SCANS` | `30` | Trial Cam scan credits for unauthenticated guests |

</Accordion>

## 6. Feature Flags

<Accordion title="YUE_OPEN_MODE">

| Field | Value |
|---|---|
| **Variable** | `YUE_OPEN_MODE` |
| **Default** | `1` (`.env.example` local default) |
| **Production override** | `0` (set in `vercel.json`) |
| **Required** | Optional |

Controls the metering and login gate behaviour:
- `0` — fail-closed: full metering and login gates enforced (production setting).
- `1` — open: Family-like limits applied, metering skipped (local development / private testing).

</Accordion>

<Accordion title="YUE_REQUIRE_LOGIN">

| Field | Value |
|---|---|
| **Variable** | `YUE_REQUIRE_LOGIN` |
| **Default** | `1` |
| **Required** | Optional |

When `YUE_OPEN_MODE=0`, set this to `1` to require sign-in before using Live mic or Cam. Set to `0` to allow anonymous access when open mode is also off.

</Accordion>

<Accordion title="YUE_ALLOW_NONCOMMERCIAL_DICTS">

| Field | Value |
|---|---|
| **Variable** | `YUE_ALLOW_NONCOMMERCIAL_DICTS` |
| **Default** | `0` |
| **Required** | Optional |

Set to `1` to enable non-commercial dictionary sources (e.g. words.hk). Leave at `0` for any paid or ad-supported deployment.

</Accordion>

<Accordion title="YUE_ENABLE_WORDSHK">

| Field | Value |
|---|---|
| **Variable** | `YUE_ENABLE_WORDSHK` |
| **Default** | `0` |
| **Required** | Optional |

Set to `1` to enable the words.hk dictionary. Requires `YUE_ALLOW_NONCOMMERCIAL_DICTS=1`. Only use on non-commercial, non-ad-supported deployments.

</Accordion>

## 7. App URL & CORS

<Accordion title="YUE_APP_URL">

| Field | Value |
|---|---|
| **Variable** | `YUE_APP_URL` |
| **Default** | `http://localhost:5173` |
| **Required** | Required in production |

The public canonical URL of the web app. Used for login/upgrade redirect links, Stripe return URLs, and CORS. Production value: `https://www.jyuttranslate.com`. The apex domain (`jyuttranslate.com`) is automatically included alongside the `www` variant.

</Accordion>

<Accordion title="YUE_CORS_ORIGINS">

| Field | Value |
|---|---|
| **Variable** | `YUE_CORS_ORIGINS` |
| **Default** | _(empty)_ |
| **Required** | Optional |

Comma-separated list of additional origins to allow in the CORS policy. The following origins are always allowed without this variable:
- `https://www.jyuttranslate.com`
- `https://jyuttranslate.com`
- `https://jyuttranslate.vercel.app`
- `http://localhost:5173` (and other common local ports)

</Accordion>

## 8. Supabase

The API uses the **service role key** (bypasses Row Level Security). The web app uses the **anon key**, either baked in at build time via `VITE_*` variables or fetched at runtime from `GET /api/auth-config`.

<Accordion title="SUPABASE_URL">

| Field | Value |
|---|---|
| **Variable** | `SUPABASE_URL` |
| **Default** | _(empty)_ |
| **Required** | Required |

Your Supabase project URL. Found in **Supabase Dashboard → Project Settings → API → Project URL** (format: `https://<project-ref>.supabase.co`).

</Accordion>

<Accordion title="SUPABASE_SERVICE_ROLE">

| Field | Value |
|---|---|
| **Variable** | `SUPABASE_SERVICE_ROLE` |
| **Default** | _(empty)_ |
| **Required** | Required |

The service role key for the API. Found in **Supabase Dashboard → Project Settings → API → Project API Keys → service_role**. Keep this secret — it bypasses all Row Level Security policies.

</Accordion>

<Accordion title="SUPABASE_ANON_KEY">

| Field | Value |
|---|---|
| **Variable** | `SUPABASE_ANON_KEY` |
| **Default** | _(empty)_ |
| **Required** | Required |

The public anon key, set on the API so it can forward the key to the web app via `GET /api/auth-config`. This must match `VITE_SUPABASE_ANON_KEY`. Found in **Supabase Dashboard → Project Settings → API → anon public**.

</Accordion>

<Accordion title="VITE_SUPABASE_ANON_KEY">

| Field | Value |
|---|---|
| **Variable** | `VITE_SUPABASE_ANON_KEY` |
| **Default** | _(empty)_ |
| **Required** | Optional (baked in at build time) |

The Supabase anon key baked into the web bundle at build time. Set in `apps/web/.env` or as a Vercel build environment variable. The app can also fetch this at runtime from the API if omitted here.

</Accordion>

<Accordion title="VITE_SUPABASE_URL">

| Field | Value |
|---|---|

| **Default** | _(empty)_ |
| **Required** | Optional (baked in at build time) |

The Supabase project URL baked into the web bundle. Set in `apps/web/.env` or as a Vercel build environment variable alongside `VITE_SUPABASE_ANON_KEY`.

|---|---|
| **Variable** | `STRIPE_SECRET_KEY` |
| **Default** | _(empty)_ |

Your Stripe secret key (`sk_live_…` or `sk_test_…`). Found in **Stripe Dashboard → Developers → API keys**.

<Accordion title="STRIPE_WEBHOOK_SECRET">

| Field | Value |

<Accordion title="RESEND_API_KEY">

| **Variable** | `RESEND_API_KEY` |
| **Default** | _(empty)_ |
| **Required** | Required for email features |

Your Resend API key (`re_…`). Found in **Resend Dashboard → API Keys**.

</Accordion>

<Accordion title="RESEND_AUDIENCE_ID">

| Field | Value |
|---|---|
| **Variable** | `RESEND_AUDIENCE_ID` |
| **Default** | _(empty)_ |
| **Required** | Optional |

The ID of your Resend Audience for contact sync and campaign broadcasts. Found in **Resend Dashboard → Audiences**. When set, new sign-ups and returning sign-ins are automatically upserted into the audience.

</Accordion>

<Accordion title="YUE_NOTIFY_FROM">

| Field | Value |
|---|---|

The verified Resend sender address in `Name <local@domain.com>` format (e.g. `JyutTranslate <notify@yourdomain.com>`). The domain must be verified in Resend. For sandbox testing only, use `JyutTranslate <onboarding@resend.dev>` — note this only delivers to the Resend account owner email.

<Accordion title="YUE_SUPPORT_FROM">

| **Default** | `JyutTranslate Help <help@jyuttranslate.com>` |

The Reply-To address on all outbound emails (auth, household invites, admin alerts). Does not need to be verified in Resend — replies are routed to this inbox.

<Accordion title="YUE_ADMIN_NOTIFY_EMAILS">

Override which email addresses receive admin notification emails (sign-ups, upgrades). Defaults to `YUE_ADMIN_EMAILS` when not set.

</Accordion>

<Accordion title="YUE_NOTIFY_WEBHOOK_SECRET">

## 11. Auth Hooks

Supabase Auth Hooks let JyutTranslate intercept user creation and send branded emails via Resend instead of Supabase's default mailer.

<Accordion title="SUPABASE_AUTH_HOOK_SECRET">

| Field | Value |
|---|---|
| **Variable** | `SUPABASE_AUTH_HOOK_SECRET` |
| **Default** | _(empty)_ |
| **Required** | Recommended |

The signing secret (format: `v1,whsec_…`) for the **Before user created** Auth Hook. Configure the hook in **Supabase Dashboard → Authentication → Hooks → Before user created** pointing to `POST /api/internal/signup-notify`. New sign-ups will trigger an admin notification email.

</Accordion>

<Accordion title="SUPABASE_SEND_EMAIL_HOOK_SECRET">

| Field | Value |
|---|---|
| **Variable** | `SUPABASE_SEND_EMAIL_HOOK_SECRET` |
| **Default** | _(empty)_ |
| **Required** | Optional |

The signing secret (format: `v1,whsec_…`) for the **Send Email** Auth Hook. Configure the hook in **Supabase Dashboard → Authentication → Hooks → Send Email** pointing to `POST /api/internal/auth-send-email`. When set, Supabase calls this hook instead of its built-in mailer for signup confirmation, magic links, recovery, and email-change messages.

<Warning>
  This hook is separate from `SUPABASE_AUTH_HOOK_SECRET`. The Before-user-created hook notifies **admins** of new sign-ups; the Send Email hook delivers **user-facing** branded auth emails.
</Warning>

</Accordion>

## 12. Admin

<Accordion title="YUE_ADMIN_EMAILS">

| Field | Value |
|---|---|
| **Variable** | `YUE_ADMIN_EMAILS` |
| **Default** | _(empty)_ |
| **Required** | Required to access admin panel |

Comma-separated list of email addresses that can access `#/admin` and call `GET /api/admin/*` routes. Matching is case-insensitive. Users on this list, or with a `role = 'admin'` assignment in the `profiles` table (migration `005`), are granted admin access.

```bash
YUE_ADMIN_EMAILS=you@example.com,colleague@example.com
```

</Accordion>

## 13. Web Push (VAPID)

Web Push notifications allow the PWA to send push messages to opted-in users. Generate VAPID keys once with `npx web-push generate-vapid-keys` and keep them stable — regenerating keys invalidates all existing subscriptions.

<Accordion title="VAPID_PUBLIC_KEY">

| Field | Value |
|---|---|
| **Variable** | `VAPID_PUBLIC_KEY` |
| **Default** | _(empty)_ |
| **Required** | Required for push notifications |

The VAPID public key shared with browsers when they subscribe to push. Also exposed to the web app via `GET /api/push/config`.

</Accordion>

<Accordion title="VAPID_PRIVATE_KEY">

| Field | Value |
|---|---|
| **Variable** | `VAPID_PRIVATE_KEY` |
| **Default** | _(empty)_ |
| **Required** | Required for push notifications |

The VAPID private key used to sign push requests. Keep this secret — never commit it to source control.

</Accordion>

<Accordion title="VAPID_SUBJECT">

| Field | Value |
|---|---|
| **Variable** | `VAPID_SUBJECT` |
| **Default** | `mailto:help@jyuttranslate.com` |
| **Required** | Required for push notifications |

Contact URI included in VAPID requests. Must be a `mailto:` or `https:` URI — Apple push services reject bare email addresses.

</Accordion>

## Web app variables (`apps/web/.env`)

The web app supports a small set of optional build-time variables for external deep links. All are commented out by default; the app works without them.

<Accordion title="Optional deep link overrides">

| Variable | Description |
|---|---|
| `VITE_TRANSLATOR_URL` | External translator URL (rarely needed — use in-app `#/app`) |
| `VITE_PRICING_URL` | External pricing / checkout URL |
| `VITE_MARKETING_URL` | External marketing site back-link from within the app |

These are baked into the web bundle at build time. For URLs you want to change without rebuilding, edit `public/site-config.json` instead (it is copied to `dist/` and served as a static file).

</Accordion>
